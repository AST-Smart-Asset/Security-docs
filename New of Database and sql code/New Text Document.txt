النتيجة بعد المراجعة:
- عدد الجداول لسه 12.
- كل الجداول الحساسة عليها Row Level Security.
- موجود 23 policy للصلاحيات.
- الباسورد بيتخزن في users.password_hash فقط، ومفيش عمود password.
- قاعدة البيانات بترفض أي قيمة مش شبه Argon2 أو bcrypt hash.
- asset_events و audit_log معمولين append-only، يعني مفيش update/delete عليهم.
- عدلت دالة has_role عشان الدور يتطبق داخل scope بتاعه فقط، ومفيش دور في كلية يفتح صلاحية في كلية تانية.
- عدلت قراءة asset_events عشان سجل النقل يفضل auditable للطرفين لو الأصل اتحرك بين مواقع/نطاقات مختلفة.

مهم جدًا: الـ database بتحمي من تخزين plain password، لكن عملية hashing نفسها لازم تحصل في الـ backend قبل الحفظ، والأفضل Argon2id. يعني التطبيق يستقبل الباسورد، يعمله hash، وبعدها يحفظ password_hash فقط.
الـ authentication كويس كتصميم DB، لكن تسجيل الدخول الكامل محتاج backend يطبق:
- password verification بـ Argon2id/bcrypt
- account lockout
- MFA لو متاح
- session/JWT آمن
- عدم السماح لأي user مباشر يوصل للـ DB ويغير app.current_user_id
الخلاصة: التصميم الآن أقوى ومناسب لمشروع فيه بيانات أصول، فواتير، ضمانات، وصلاحيات scoped. مفيش plain passwords، والـ authorization اتقفل أفضل بعد التعديل.
